# 一步一脚印 · Baby Steps

原创第三人称物理步行游戏。分别控制两只脚，沿便便山的两圈盘山路上行，穿过两座独木桥，抵达山顶黄金马桶。桌面键鼠／手柄、单人、本地离线运行；厨房项目的地图、依赖和存档保持独立。

## 从零重建

见 [从零 Vibe Coding 技术文档](docs/VIBE-CODING-TECH-SPEC.zh-CN.md)：包含架构、物理控制、分阶段开发提示词与验收标准。

## 启动与构建

双击 `Start-BabySteps.cmd`。需要 Node.js 20 或更新版本；已有构建可离线启动。启动器检查源码和 `public/`，按需构建，默认端口 5190，占用时尝试后续端口，复用同项目服务。

```powershell
npm install             # 首次安装需要联网
npm run dev             # http://127.0.0.1:5190/
npm test
npm run build
npm start               # 从 dist 启动本地生产服务
```

游玩使用本地 GLB、合成音效及已打包的 Rapier WASM，无 CDN。不能直接双击 `dist/index.html`。Chrome / Edge 需要支持 WebGL2 和鼠标锁定。

## 操作

| 操作 | 方法 |
| --- | --- |
| 抬左脚 / 右脚 | 按住鼠标左键 / 右键 |
| 调整落点 | 按住对应键拖动，向上前进、向下后退，左右横移 |
| 落脚 | 松开对应鼠标键，等待实际接地 |
| 调整重心 | W / ↑ 前倾，A / ← 左倾，S / ↓ 后倾，D / → 右倾 |
| 观察 | 无鼠标键按下时，直接移动鼠标转镜头 |
| 镜头距离 | 滚轮 |
| 暂停 / 释放鼠标 | Esc |
| 返回检查点 | R，同时重置松散道具 |
| 倒地后起身 | 地面稳定且空间安全时自动进行 |

Q / E 不参与普通玩法。学会正常行走前，鼠标两键同时按下时保留先按的脚，另一个键必须松开再按。拖脚冻结镜头，全部鼠标键松开后恢复观察。落点方向相对开始拖动时的镜头，每像素目标位移 0.0035 米，鼠标位移不乘帧时间。

起点附近的 Daniela 以半透明投影出现。走近后触发她与 Dario 的四段对话，文字自动播放，也可按 Enter / 空格或手柄 A / × 继续。走远会收起尚未完成的对话，再次靠近从头播放；读完后记录到当前存档，继续旅程不会重复触发，重新出发会重置。暂停和开发调试模式会冻结对话。

到达第一个存档点（进度 12）后，前方 18–24 段是「Scaling Laws」跷跷板关卡。木桥由真实铰链支撑，会随脚下承重缓慢倾斜；小步越过支点，等桥面稳住再换脚。桥头的 Sam Altman 记忆投影会与 Dario 对话，沿用 Enter / 空格、手柄 A / × 和自动播放。两位 NPC 的已读状态独立保存；R 返回存档点时重置桥面，重新出发才清除已读状态。

跷跷板后的存档点（进度 28）放有「人类反馈小饼干」，Sam 会在此等候。到达存档点并靠近饼干后会自动吃下，永久解锁本次旅程的正常行走和跳跃，并立即触发三段奖励对话。之后 WASD／方向键或左摇杆按镜头方向移动，双腿自动交替，鼠标／右摇杆观察；按空格或手柄 A / × 起跳，落地后可以再次跳跃，长按不会连续起跳。对话期间空格和 A / × 只推进对话。鼠标双键和扳机不再需要拖脚。能力没有计时限制，跌倒、滑回山脚、返回存档点和刷新续玩都保留；选择重新出发会重置能力和饼干。奖励对话期间暂停移动，读完即可出发。

学会正常行走、读完奖励对白后，玩家继续照常控制 Dario 前进，他每走过一段相等的路程便说一句自白。进度 28 至 180 的剩余路线按水平路径长度分成 13 等份，前 12 个等距触发点依次显示原文的 12 句，最后一段留给玩家走到终点。字幕不会接管行走，移动、跳跃、观察和返回存档点照常使用；只有前进到新的触发点才会触发后续句子，返回已走过的路段不会重播已读句子。字幕自动收起，也可按 Enter 收起当前句。暂停和开发调试模式会冻结播放，已读句子保存到当前旅程，继续游戏不会重播，重新出发会重置。抵达黄金马桶后进入结束动画。

山顶由不透明的金色发光半球罩遮住，罩面有流光和闪烁光点。Dario 的身体接触罩子后，整个罩子立即消失，露出山顶和黄金马桶。触碰按三维位置判断，经过山下不会误触；罩子不阻挡行走。揭示状态随存档保存，返回存档点或继续游戏不会重新出现，重新出发会恢复。

走到黄金马桶旁会自动全屏播放 `public/media/ending.mp4`（约 5.5 秒，音轨遵循静音设置），游戏运动和计时同时停止。播放完后保持视频最后一帧，不循环或弹出结算菜单。末帧使用原视频第 165 帧提取的 `public/media/ending-last-frame.png`，避免浏览器在播放结束时清空画面。刷新页面可开始新旅程。

支持浏览器提供 **standard 标准映射**的手柄（常见 Xbox / PlayStation 手柄，实际识别取决于系统和浏览器）。连接后先按任意键让浏览器识别，再按 Start / Options 开始或继续；手柄游玩无需鼠标锁定。

| 手柄操作 | 方法 |
| --- | --- |
| 抬左脚 / 右脚 | 按住 LT / L2、RT / R2；松开落脚 |
| 调整落点 | 抬脚时推右摇杆，上推向前；方向相对选脚时的镜头 |
| 观察 | 未按选脚键时推右摇杆 |
| 调整重心 | 左摇杆，轻推可微调，方向相对角色 |
| 镜头距离 | 游玩时十字键 ↑↓ |
| 暂停 / 继续 | Start / Options |
| 返回检查点 | Y / △ |
| 菜单 | 十字键 ↑↓ 选择，A / × 确认，B / ○ 返回首页 |

摇杆采用 18% 径向死区，扳机按下阈值 55%、释放阈值 35%，防止漂移和阈值附近重复抬落脚。右摇杆落点速度最高 0.65 米/秒，按固定物理步积分，不受渲染帧率影响；参数集中在 `src/gamepad.ts`。两个扳机先按的优先，被忽略的扳机必须松开再按；同一采样首次同时按下时优先左脚。鼠标和手柄共享选脚归属，其他控制源不能释放当前脚。

失焦、暂停、跌倒、起身完成或返回检查点后，需要松开扳机、摇杆回中，再重新操控。手柄断连会暂停；重新连接后按 Start 继续，不会自动恢复。点击游戏画面可切回键鼠并请求鼠标锁定，按手柄操作可切回手柄。菜单保留鼠标按钮；手柄菜单提供开始、继续、静音和返回首页，重新出发按钮仍可用鼠标操作。若浏览器阻止自动播放声音，可点击右上角音符启用。非标准映射或接口不可用时显示提示，键鼠仍可游玩。

学会正常行走前，WASD 与方向键只控制上身，不改变脚部目标。方向相对角色朝向，别名不叠加、反向抵消、斜向归一化，约 0.18 秒平滑响应。为恢复人体活动范围，本版取消旧的无限旋转：前倾意图最多约 40°，后倾与侧倾约 25°，实际姿态还受关节、碰撞和力矩限制。松开回正。

绿色脚印表示当前可及，黄色表示过远，红色表示悬空或路径受阻。目标光标限制在身体周围 0.85 米以内；这不是保证能跨 0.85 米。每条腿由两个固定 0.43 米骨段组成，高差、身体位置和障碍共同决定真实可达范围，不再拉长腿来够落点。

身体会自动配合移重心，平地无需持续按前倾。平地屈髋、收膝与调整落点同步进行，目标抬脚高度随步幅约为 0.20–0.30 米；松键即开始下降，并根据脚与落点的实际距离协调下降幅度，避免提前踩地拖行。快速点击不再强制完成一次高抬腿。检测到前方台阶或双脚高差时，采用约 0.40 米的高抬腿，先越过边缘再落下。实际高度和速度始终受关节、碰撞及承重限制。

摆动腿的关节响应加快，支撑腿保留平稳的承重响应；平地换步减少沿迈步方向的制动，侧向稳定与摩擦限制继续有效。身体不会因移动镜头而平移。脚步声与计步只来自玩家实际调整落点后的真实接触，不因原地点击、倾斜、倒地或起身产生。

## 物理模型及边界

以下动态身体控制描述适用于吃饼干前，以及吃饼干后跌落、滑行和起身的状态。学会正常行走后，使用 Rapier 胶囊角色控制器处理墙壁、台阶、斜坡和重力，原有角色骨骼播放自动交替步态；遇到明显落差会交回动态身体，起身后恢复正常行走。

- 固定 120 Hz，先控制、再求解碰撞、最后读取接触；所有身体部位的位置与旋转均插值显示。
- 约 1.8 米、总质量 80 kg（含背包）。骨盆、躯干、头、双上臂、前臂、手、大腿、小腿和鞋共 15 个动态刚体，14 个持久身体关节；相邻部位不互相挤压，其他部位可发生自碰撞。
- 膝和肘使用有范围的铰链，其他身体关节使用受限角度与最大力矩的电机。腿长固定，鞋始终动态，站立、跌倒、起身不切换到运动学刚体，也不瞬间清空速度。
- 实际碰撞产生法向载荷、摩擦和反弹；材质区分土、石、木和橡胶。起步、摆腿、承重变化均连续进行，没有旧版的长步落地额外推力或“超过角度 / 时间就强制摔倒”的判定。
- 倒地状态用于识别已经发生的身体接地。失衡、滑动、绊住和撞击先由刚体求解产生，再转入放松和起身流程。
- **保留有限的游戏平衡辅助**：有真实支撑接触时，通过有上限的虚拟承重力和姿态力矩帮助身体，水平力受表面摩擦限制，对承载的动态物体施加反作用。它是对人体肌肉与承重传递的近似，并非逐条肌肉的生物力学仿真；其承重与 Rapier 鞋底接触载荷分别记录。无接触时不提供升力或方向控制。
- 安全倒地稳定后，寻找半径 0.5 米内的双脚落点，高差不超过 0.3 米，检查上方站立空间。约 3–4 秒用力收腿、撑起、站稳；保持动态碰撞，受阻时等待或中止，可用 R 重试。起身中可以观察、暂停，完成后需重新按键。

固定地形、山体、岩石、树干、路牌和旗杆具有碰撞；可见圆木桥为锚定的桥梁，保持圆柱曲面。新地图检查点附近的小石头是动态道具，可以踢动、滚落和互相碰撞；桥梁保持固定。木材密度约 620 kg/m³、石材约 2600 kg/m³，几何与质量共同影响惯性。

风产生二次阻力。便便山地图没有峡谷水域；底层仍保留经测试的浮力、水阻和材质模块。旗布只做视觉摆动，不包含布料或破碎模拟。

R、新旅程、返回首页及刷新续玩会恢复松散道具的初始姿态；普通跌倒和原地起身保留物品变化。

## 路线、暂停和存档

当前地图来自 Teach-Dario2Toilet：便便山、两圈盘山路、山顶黄金马桶。泥土山路包含连续起伏、变化的宽度和粗糙土层，检查点及桥头保留平整站位。山脚研究所、Claude 星芒、厕纸补给与皮搋子神坛组成轻松的恶搞彩蛋。路线参数 0–180 表示设计进度，不是严格弧长；山顶约高 22 米。独木桥位于 56–64、114–122 段，检查点为 0、12、28、48、68、90、108、128、146、164、180。

桥下的低摩擦泥土滑沟贴着山体盘旋下降，两条入口汇入共同的下段沟槽直达山脚。掉桥后保持动态身体连续滑下，清空登山检查点；滑行中 R / Y 无效，可以暂停，实际接地后再退出滑行并尝试起身。普通地面摔倒仍可原地起身。完整设计见 [场景设计](docs/SCENE-DESIGN.zh-CN.md)，迁移范围见 [地图替换说明](docs/MAP-MIGRATION.md)。

本项目保留原来的第三人称、角色、键鼠/手柄和镜头缩放；到达山顶仍按原有规则结算，没有引入另一个项目的第一人称、便意或 F 键入座演出。

失焦、标签隐藏、鼠标解锁自动暂停，清空输入和积累位移；继续时重新锁鼠标，不补算后台时间。暂停可冻结起身。HUD 显示脚、承重状态、进度、有效时间、步数和跌倒次数。

新地图独立使用 `baby-steps:save:poop-mountain:v1`，数据带地图标识，记录检查点、用时、跌倒、步数和本地图最佳成绩。旧 `baby-steps:save:v1` 保持原样，不将旧检查点恢复到新山路；首次进入新地图从山脚开始。静音设置继续沿用。每五秒、检查点、暂停和退出时保存。继续从安全检查点恢复，不恢复空中姿态或道具中间状态。存档不可用时仍可游玩。

## 美术与调试

`public/models/` 是运行时 GLB，`exports/glb/` 包含分件、清单和完整静态场景。角色使用 `Dariov2.glb` 的 Mixamo 蒙皮骨骼，通过 `src/dario.ts` 跟随角色姿态。Sam 使用用户提供的 `SAM.glb`，保留原始蒙皮和贴图，在桥头及奖励存档点共用同一角色；运行时规范为约 1.8 米高的半透明投影并朝向 Dario，对话时投影略微增强。地图生成保留人物原始文件。普通构建不重新生成模型。

```powershell
npm run assets:generate  # 生成 public/models
npm run export:glb       # 导出分件、完整场景、清单
npm run test:browser
npm run test:assets
npm run test:production
npm run test:gamepad      # 需开发服务；虚拟标准手柄浏览器验证
npm run test:daniela      # 需开发服务；投影、对话及存档回归
npm run test:sam          # 需开发服务；跷跷板、Sam 对话及存档回归
npm run test:reward       # 需开发服务；自动吃饼干、正常行走、跳跃、奖励对话与存档回归
```

显式导出会覆盖对应文件；手工编辑请先备份。资产约定见 [GLB-ASSETS.md](docs/GLB-ASSETS.md)。Rapier 独立升级为 0.21.0，以使用可限制最大力矩的球关节电机，厨房依赖未修改。

开发地址加 `?physicsDebug=1` 显示物理碰撞轮廓，方便检查鞋、骨骼、道具与场景。自动测试涵盖输入、解剖约束、空气中的重力与动量、实际接触、连续小步、自然倒地、动态起身、碰撞间隙、浮力、道具重置、存档和路线回放；浏览器覆盖鼠标、镜头、暂停、续玩与两种布局。

游戏中按 `2` 进入人物放置模式：鼠标转动镜头时人物始终跟随镜头的水平朝向，`Z` / `X` 也可同时转动人物与镜头。`WASD` / 方向键平移，`Q` / `E` 降低或抬高，Shift 加速，左键放到镜头中心指向的地面；再次按 `2` 退出并保留位置与朝向。

新地图完整场景验证：先启动开发服务，再执行 `npm run test:scene`，验证两座桥各三个位置的内外侧跌落、持续留在泥沟中滑至山脚及检查点归零。`npm test` 包含盘山路起步回放；`npm run test:route:browser` 是可选的长路线诊断，尚未作为完整人工通关证据。验证边界见 [物理验证说明](docs/PHYSICS-VALIDATION.md)。
